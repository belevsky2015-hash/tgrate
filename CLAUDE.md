# Брифинг для агента

Ты разворачиваешь и дальше ведёшь этот проект на VPS владельца. Прочитай
`README.md` — там предметная часть. Здесь только то, что нужно знать, чтобы
не сломать логику и не выдать владельцу неверные цифры.

## Что это

Калькулятор реального курса перевода через Крипто Кошелёк Telegram. Считает,
сколько придёт на выходе с учётом всех комиссий P2P Маркета, внутреннего
обмена и вывода в сеть. Две точки входа: веб-панель и юзербот на готовой
сессии владельца.

Цель по точности — расхождение с фактом в пределах нескольких процентов.
Всё в проекте подчинено этому. Если правка делает вывод удобнее, но менее
точным — она вредна.

## Порядок первого запуска

1. `cp .env.example .env`. Владелец вписывает `WALLET_API_KEY` (Кошелёк →
   Deposit → P2P Market → My Profile → API Keys) и данные сессии. Без ключа
   Wallet проект запустится, но P2P-маршрутов не будет — это не поломка,
   а ожидаемое поведение, скажи об этом прямо.
2. `make install`
3. `make check` — обязательно. Скрипт проверяет ключ, живость стакана и
   автоматически определяет семантику поля `side` (см. ниже). Не разворачивай
   дальше, пока он не пройдёт.
4. `make test` — тесты движка комиссий, сети не требуют.
5. `make run` для проверки руками, потом `deploy/install.sh` для systemd.

Панель по умолчанию слушает 127.0.0.1. Наружу — только через nginx с TLS и с
непустым `PANEL_TOKEN`. Не выставляй uvicorn в интернет напрямую.

`make install` зовёт `python3 -m venv`, а на этом хосте нет `python3-venv`.
Если `.venv` пришлось пересоздавать — `uv venv -p /usr/bin/python3 .venv &&
uv pip install --python .venv/bin/python -r requirements.txt` (`install`, не
`sync`: `requirements.txt` ручной, `sync` не дотянет транзитивные зависимости).

Один тест: `.venv/bin/python -m pytest tests/test_engine.py::test_имя -q`.
Имена тестов — транслит (`test_taker_ne_platit_a_maker_platit`).

## Как течёт расчёт

1. `QuoteBook.refresh` (`app/quotes.py`) раз в 30 с (фоновый `_loop` в
   `app/main.py`) собирает все котировки в один плоский словарь `book.last`
   с ключами вида `источник:ПАРА:сторона` — `wallet:USDT/RUB:bid`,
   `cex:GRAMUSDT:ask_inv`, `binance_p2p:USDT/KZT:bid`. Значение — **множитель в
   направлении ребра**, поэтому цены покупки хранятся перевёрнутыми
   (`:ask = 1/price`).
2. `fees.yaml` грузится один раз при импорте `app/main.py` (`load_graph`,
   переменные `${exchange_fee}`, `${p2p_fee_rub}`, `${p2p_fee_kzt}`… из
   `W.fee_vars` по `WALLET_TIER`/`WALLET_P2P_ROLE`). Правка yaml или `.env` —
   только с рестартом процесса.
3. `/api/quote` не берёт `book.last` как есть: `book.at_depth` пересчитывает
   стакан Wallet на сумму запроса (`_usd_depth`) — объявления кешированы на
   30 с, лишних запросов нет. `book.last` остаётся срезом на 1000 USDT для
   истории; его `wallet:`-ключи в расчёт запроса не подмешиваются — нет цены
   на эту сумму, значит маршрут выпадает. Поле `pay` запроса
   (`{"EUR": ["sepainstant"]}`) заменяет `WALLET_PAYMENTS` для этого расчёта;
   выбор в панели — из `/api/methods`, то есть из живого стакана. История есть
   только для способов из `.env`. `bind_rates` связывает поле `rate:` ребра с ключом.
   Нет котировки → ставит `rate = 0`, ребро выпадает, ключ уходит в
   `missing_quotes` ответа. Это и есть «честный пропуск маршрута».
4. `k_best_routes` (`app/graph.py`) → `Edge`/`Route` (`app/models.py`
   применяет процент и фикс) → `Calibrator.factor` по ключу маршрута и паре →
   минус `SAFETY_PCT`.

`app/history.py` пишет в ту же SQLite (`data/`), что и калибровка, не курс
пары, а весь срез `book.last`; график любого направления пересчитывается тем
же поиском маршрута. Срезы помечены `_model`; срезы старой модели (до
27.09.2026, без лимитов объявлений) в график не идут — не «чинить». Для
маршрутов из `TRACK_ROUTES` цикл раз в минуту пишет точный итог на заданную
сумму в таблицу `tracked` вместе с ценой крипты на каждом шаге (`legs`:
RUB за USDT, EUR за USDT…), и `/api/history` на ту же сумму берёт его;
`legs_meta` подписывает ряды и говорит, какая сторона цены выгодна. `app/providers/` — спот (курс внутреннего обмена) и
Binance P2P (только сравнение).

Юзербот (`app/userbot.py`) не считает сам: ходит в HTTP-API панели по
`API_BASE`. Без живой панели он бесполезен.

## Развёртывание

Прод — копия в `/opt/tgrate`, **системные** юниты `tgrate-api` (uvicorn
127.0.0.1:8080) и `tgrate-bot`, не `--user`. Правка здесь туда сама не
попадает: `sudo deploy/install.sh` делает rsync без `.venv`, `.git`, `data`,
пересобирает venv через uv. Юниты он делает `enable --now`, а это уже
запущенный сервис **не перезапускает** — после повторного деплоя нужен
`sudo systemctl restart tgrate-api tgrate-bot`. `sudo` отсюда недоступен —
отдавай владельцу строкой. Логи: `journalctl -u tgrate-api -u tgrate-bot -f`.

## Главная неопределённость

В документации Wallet не сказано, чью сторону описывает поле `side` в
объявлении. От этого зависит, какую цену мы считаем ценой покупки. Ошибка
здесь переворачивает спред и даёт стабильно неверный курс.

`scripts/check.py` определяет это сам: у объявлений на продажу цена обязана
быть выше, чем у объявлений на покупку. Скрипт скажет, какое значение
поставить в `WALLET_SIDE_WHEN_BUYING`. Если разница между сторонами меньше
0,1% — стакан пустой или сломанный, не угадывай, сообщи владельцу.

## Что нельзя менять не подумав

**Комиссии живут в двух местах и только там.** `app/wallet.py` — константы
тарифов Кошелька, `fees.yaml` — граф операций. Не хардкодь проценты в коде
расчёта. Если владелец получил тариф Трейдер, меняется `WALLET_TIER` в `.env`,
а не числа в yaml.

**Роль на P2P.** `WALLET_P2P_ROLE=taker` означает, что владелец откликается
на чужие объявления и платит 0. `maker` — размещает свои и платит по валюте:
RUB 2%, KZT/UAH/USD/EUR/TRY 1,2% (тариф с 10.08.2026, у «Надёжного продавца»
1,6% и 0,9%). Это не косметика, это ровно столько в прогнозе. Спроси
владельца, как он торгует на самом деле, если не уверен.

**Цена P2P-ноги.** `WalletP2P.quote` выбирает цену в таком порядке:
1) лучший надёжный мейкер, который берёт всю сумму одной сделкой (`top_offers`
— он же первый в топ-3 панели); 2) VWAP по надёжным, если одной сделкой не
закрыть; 3) VWAP по всему стакану с пометкой в `basis`. Каждый кусок VWAP
обязан влезть в `minAmount`/`maxAmount` объявления (`fill`). Не заменяй это
на первую строку стакана: 27.09.2026 первая строка «ровно 100 000 ₽» и VWAP
без лимитов расходились с реальным предложением на 3–8%. Надёжный — статус
`TRUSTED_MERCHANT` или от 95% исполнения и 250 сделок (порог статуса из
help.ru.wallet.tg, статья 129).

**Калибровка.** `app/calibration.py` хранит отношение факта к прогнозу и
подкручивает расчёт. Затухание по свежести, медианная защита от выбросов,
потолок поправки 8%. Не поднимай потолок: если модель врёт больше чем на 8%,
сломана модель, а не коэффициент, и это надо чинить в `fees.yaml`.

**Поиск маршрута.** Дейкстра на максимум выхода корректна только потому, что
каждая операция монотонна по входной сумме. Если добавишь ребро с невозрастающей
функцией (например, комиссию, которая падает с суммой ступенькой вниз так, что
меньший вход даёт больший выход), поиск перестанет быть точным. Такое ребро
надо разбивать на несколько с разными лимитами.

## Частые задачи

**Новая валюта.** Добавь узел и пару рёбер `p2p.buy.X` / `p2p.sell.X` в
`fees.yaml`, добавь код в `FIATS` в `app/quotes.py`. Больше нигде.

**Wallet поменял комиссии.** Правь `app/wallet.py` и `fees.yaml`, сверяясь с
help.ru.wallet.tg. Поставь дату сверки в комментарий.

**Автосбор сделок.** В `app/userbot.py` есть обработчик уведомлений от
@wallet с выключенной автозаписью. Формулировки уведомлений у всех разные:
пусть владелец пришлёт несколько реальных через `.raw`, подгони регулярки,
потом включай. Не включай вслепую — мусор в калибровке хуже её отсутствия.

**Ошибка 429 от Wallet.** Стакан обновляется раз в 30 секунд, чаще опрашивать
нечего. Увеличивай интервал в `_loop`, не добавляй ретраи в цикле.

## Оформление

**Читай `DESIGN.md` в корне проекта до любой правки вида.**

Панель сведена с остальными панелями узла 05.09.2026: оформление общее, живёт
в проекте `hostpanel` (`design.md` — правила, `tokens.css` — значения) и
отдаётся по `/tokens.css`. Адрес у панелей общий, поэтому путь работает и
отсюда.

Три вещи здесь выглядят как недоделки, но сделаны намеренно, и `DESIGN.md`
объясняет каждую: у полосы перехода нет своего стиля, на входе `:8080` она
скрыта, а `--pad-x` больше не считает вставки корпуса. Не «чинить» их, не
прочитав файл.

Тема больше не обсуждается: тёмный набор убран, все панели узла светлые.

## Чего не делать

**Маршрут без настоящей цены — не маршрут.** Владелец требует фактически
правдивый расчёт: если цифра шага не взята из реальных данных, ребра в графе
быть не должно. Поэтому 27.09.2026 убраны: покупка и продажа картой (курс
провайдера не виден, стоял курс ЦБ ± 2%), запас `spread_pct` на P2P-рёбрах
(цена там — предложение конкретного продавца), наценка 1% при недоборе
объёма (стакан не закрывает сумму → котировки нет, маршрут выпадает) и курс
ЦБ целиком. Единственное оставленное приближение — обмен USDT↔GRAM/BTC по
споту Binance/Bybit: API курса у Кошелька нет, шаг подписан в `note`.

Не предлагай торговать через P2P API — он только на чтение, размещать и
закрывать сделки можно лишь в интерфейсе Кошелька.

Не подставляй курс Binance вместо Wallet, если API кошелька недоступен.
Лучше честно показать пропуск маршрута, чем цифру, которая выглядит настоящей.
Binance в проекте есть только для сравнения в `.статус`: та же `fill` на той
же глубине, мейкеры от 95% исполнения. Расхождение Wallet с Binance на 3–10%
по KZT/UAH/TRY — свойство рынка Wallet, а не ошибка модели; не «подтягивай»
к нему прогноз.

Не отключай `PANEL_TOKEN` на публичном адресе, даже временно.
