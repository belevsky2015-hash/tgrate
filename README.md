# Калькулятор курса через Telegram Wallet

Веб-панель и юзербот, которые считают, сколько реально придёт на выходе, если
прогонять деньги через Крипто Кошелёк Telegram: P2P Маркет, внутренний обмен,
вывод в сеть.

## Что выяснилось про Wallet

Проверено по help.ru.wallet.tg и docs.wallet.tg 27.09.2026. Кошелёк меняет
тарифы, поэтому всё вынесено в `fees.yaml` и `app/wallet.py`.

**У Wallet есть официальный P2P API.** Это главное. Не нужны ни парсинг
мини-аппа, ни оценки по чужим биржам:

```
POST https://p2p.walletbot.me/p2p/integration-api/v1/item/online
X-API-Key: <ключ>
{"cryptoCurrency":"USDT","fiatCurrency":"RUB","side":"SELL","page":1,"pageSize":50}
```

Ключ берётся в самом Кошельке: Deposit → P2P Market → My Profile → API Keys.
Бесплатно, до 10 ключей. Отдаёт цену, лимиты, доступный объём, методы оплаты,
рейтинг мейкера. Данные обновляются раз в 30 секунд — чаще опрашивать незачем.
Торговать через API нельзя, только читать цены.

**Комиссии, которые определяют всё:**

| Операция | Сколько |
|---|---|
| P2P Маркет | только с мейкера: RUB 2%, KZT/UAH/USD/EUR/TRY 1,2% (у «Надёжного продавца» 1,6% и 0,9%) |
| Обмен внутри Кошелька | 0,9% на Базовом, 0,09% на Трейдере |
| Вывод USDT в сети TON | 1 USDT фиксированно |
| Вывод USDT в TRON | 3,5 USDT фиксированно |
| Вывод GRAM (бывший TON) | 0,05 GRAM |
| Вывод BTC | 0,00008 BTC, плавающая |
| Пополнение | 0 |
| Перевод контакту в Telegram | 0 |
| Продажа на карту через партнёра | 3,5% (в расчёт не входит — курс провайдера не виден) |

Три вывода из этой таблицы:

1. **Мейкер или тейкер — самый крупный рычаг.** Откликаясь на чужое
   объявление, вы не платите ничего; разместив своё, платите 1,2–2%. Ставьте
   `WALLET_P2P_ROLE` честно, иначе прогноз промахнётся ровно на эту величину.
2. **Фиксированный вывод убивает мелкие суммы.** 3,5 USDT в TRON — это 3,5%
   на сотне долларов и 0,07% на пяти тысячах. Расчёт это учитывает, поэтому на
   маленьких суммах панель почти всегда предложит сеть TON.
3. **Тариф Трейдер меняет обмен в десять раз** — 0,9% против 0,09%. Порог:
   оборот 50 000 $ за календарный месяц, P2P и карта в оборот не идут.

Лимиты обмена: 1,4–25 000 USDT на пару, пары с BTC — от 3,1, USDT–BTC — до
100 000, USDT–SOL — до 50 000, USDT–ETH — до 100 000. Минимумы вывода: 1 USDT, 0,0001 BTC, 0,1 GRAM.

## Откуда берётся точность

Три вещи, каждая по отдельности стоит около процента.

**Стакан на вашу сумму, а не верхняя строка.** Цена P2P берётся у лучшего
надёжного мейкера, который закроет всю сумму одной сделкой, — с учётом его
`minAmount`/`maxAmount` и доступного объёма. Если одной сделкой не закрыть,
средневзвешенная по нескольким надёжным, каждый кусок в лимитах объявления.
Верхняя строка стакана часто вообще недоступна: «91 ₽, но только ровно
100 000 ₽». На 27.09.2026 это давало ошибку до 8%. Панель показывает топ-3
надёжных, у которых можно открыть сделку прямо сейчас.

**Фильтр по контрагентам.** Надёжный — статус Кошелька «Надёжный продавец»
или от 95% исполнения и 250 сделок, как в требованиях к статусу. Мейкеры ниже
`WALLET_MIN_EXECUTE_RATE` не идут в расчёт вовсе.

**Калибровка по факту.** После сделки в панель вводится реальная полученная
сумма. Система хранит отношение факта к прогнозу и применяет поправку с
экспоненциальным затуханием по свежести и медианной защитой от выбросов.
Через несколько сделок на направление модель садится на реальность. Пока
записей нет, панель честно пишет, что поправки нет и цифра держится только на
модели комиссий.

## Запуск

```bash
make install     # venv, зависимости, .env из шаблона
# впишите в .env WALLET_API_KEY и данные сессии
make check       # ключ, живой стакан, автопроверка семантики side
make test        # тесты движка комиссий, сеть не нужна
make run         # панель на 127.0.0.1:8080
make bot         # юзербот отдельным процессом
```

Строку сессии, если её нет под рукой: `make session`. Скрипт подхватит
существующий файл `.session`, повторно авторизовываться не придётся.

На VPS под systemd:

```bash
sudo deploy/install.sh     # ставит в /opt/tgrate, поднимает оба юнита
make logs
```

`make check` заодно решает единственную неопределённость в проекте:
документация Wallet не говорит, чью сторону описывает поле `side`
в объявлении, а от этого зависит, какую цену считать ценой покупки. Скрипт
сравнивает средние цены обеих сторон — у продавцов они обязаны быть выше — и
сам говорит, что поставить в `WALLET_SIDE_WHEN_BUYING`. Не запускайте панель,
пока проверка не прошла: ошибка здесь переворачивает спред.

Наружу — только через `deploy/nginx.conf` с TLS и непустым `PANEL_TOKEN`.
Юзербот работает на полном доступе к аккаунту, открытая панель этого не
заслуживает. Есть и `docker compose up -d`, если так привычнее.

## Структура

```
CLAUDE.md           брифинг для агента: инварианты и частые задачи
fees.yaml           граф операций и все комиссии
app/wallet.py       клиент P2P API и тарифы Кошелька
app/graph.py        поиск лучших маршрутов
app/models.py       применение комиссий к сумме
app/calibration.py  поправки по реальным сделкам
app/quotes.py       агрегатор источников
app/main.py         API панели
app/userbot.py      Telethon на готовой сессии
static/index.html   панель
scripts/check.py    самопроверка перед запуском
scripts/session.py  получение StringSession
tests/              тесты движка
deploy/             systemd, nginx, установщик
```

Поиск маршрута — Дейкстра на максимум выхода. Это корректно, потому что каждая
операция монотонна по входной сумме: больше зашло — не меньше вышло.
Ограничение в 6 шагов, циклы исключены.

Binance P2P опрашивается только для сравнения — в `.статус` видно, насколько
Wallet отличается от рынка по каждой валюте. В расчёт маршрута он не входит.
