# tgrate — реальный итог обмена через Telegram Wallet

🇬🇧 [English version](README.md)

Веб-панель и юзербот Telegram, которые считают, сколько реально придёт на
выходе, если прогонять деньги через Крипто Кошелёк Telegram: P2P Маркет,
внутренний обмен, вывод в сеть. Находит лучший маршрут между двумя точками
(например, рубли на карте → USDT в Кошельке → USDT в сети TON), применяет
каждую комиссию на каждом шаге и показывает, у каких надёжных продавцов
сделку можно открыть прямо сейчас.

**Стек:** Python 3.12, FastAPI + uvicorn, Telethon, httpx, SQLite, pytest.

---

## Что умеет

- **Лучший маршрут** между банками, балансами Кошелька и сетями (RUB, KZT,
  UAH, USD, EUR, TRY; USDT, GRAM, BTC, USDC в Кошельке; USDT в TON / TRON /
  Solana / Ethereum, GRAM и BTC в своих сетях; перевод контакту в Telegram) —
  с комиссией и итогом каждого шага.
- **Цена P2P на вашу сумму**, а не верхняя строка стакана (см. «Откуда берётся
  точность»).
- **Топ-3 надёжных продавцов/покупателей** на каждый P2P-шаг: ник, цена,
  лимиты, процент исполнения, число сделок, время оплаты.
- **Выбор способа оплаты** (СБП, карты банков, SEPA, Revolut, Wise…) — список
  берётся из живого стакана.
- **Отслеживаемые маршруты:** точный итог на заданную сумму раз в минуту
  (`TRACK_ROUTES`), графиком в панели.
- **Калибровка по реальным сделкам:** вводите, сколько реально пришло, и
  прогноз по этому направлению подстраивается.
- **Юзербот** на вашем аккаунте Telegram: тот же расчёт командой в «Избранном»
  или любом чате.

## Откуда берётся точность

Три вещи, каждая по отдельности стоит около процента.

**Стакан на вашу сумму.** Цена P2P берётся у лучшего надёжного мейкера,
который закроет всю сумму одной сделкой, — с учётом `minAmount` / `maxAmount`
объявления и доступного объёма. Если одной сделкой не закрыть —
средневзвешенная по нескольким надёжным, каждый кусок в лимитах объявления.
Верхняя строка стакана часто недоступна («91 ₽, но только ровно 100 000 ₽»);
без учёта лимитов ошибка доходила до 8%.

**Фильтр по контрагентам.** Надёжный — статус Кошелька «Надёжный продавец»
или от 95% исполнения и 250 сделок (как в требованиях к статусу). Мейкеры ниже
`WALLET_MIN_EXECUTE_RATE` в расчёт не идут вовсе.

**Калибровка по факту.** После сделки полученная сумма записывается (в
панели, через `/api/deals` или `.факт` в юзерботе). Для каждого маршрута и
пары хранится отношение факта к прогнозу, и применяется поправка: вес по
свежести (полураспад 21 день), среднее пополам с медианой против выбросов,
отношения вне 0,5–2 отбрасываются, нужно минимум 3 сделки, потолок ±8%.
Отношение меряется от модели без поправки, поэтому поправка не раскачивается.
Пока сделок нет, панель честно пишет об этом, и цифра держится только на
модели комиссий.

## Комиссии

Сверено с help.ru.wallet.tg и docs.wallet.tg 27.09.2026. Кошелёк меняет
тарифы, поэтому все числа — в `app/wallet.py` и `fees.yaml`.

| Операция | Сколько |
|---|---|
| P2P Маркет | только с мейкера: RUB 2%, KZT/UAH/USD/EUR/TRY 1,2% («Надёжный продавец»: 1,6% / 0,9%); тейкер платит 0 |
| Обмен внутри Кошелька | 0,9% на Базовом, 0,09% на Трейдере |
| Вывод USDT: TON / TRON / Solana / Ethereum | 1 / 3,5 / 1,5 / 4 USDT, фиксированно |
| Вывод GRAM (бывший TON) | 0,05 GRAM |
| Вывод BTC | 0,00008 BTC, плавающая |
| Пополнение, перевод контакту в Telegram | 0 |
| Продажа крипты на карту через партнёра | 3,5% — в граф маршрутов не входит, курс провайдера не виден |

Что из этого следует:

1. **Мейкер или тейкер — самый крупный рычаг.** Откликаясь на чужое
   объявление, вы не платите ничего; разместив своё — 1,2–2%. Ставьте
   `WALLET_P2P_ROLE` честно.
2. **Фиксированный вывод убивает мелкие суммы.** 3,5 USDT в TRON — это 3,5% на
   сотне долларов и 0,07% на пяти тысячах, поэтому на маленьких суммах маршрут
   почти всегда идёт через TON.
3. **Тариф Трейдер делает обмен в десять раз дешевле** (0,9% → 0,09%); порог —
   оборот 50 000 $ в месяц.

Лимиты обмена (в долларовом эквиваленте): 1,4–25 000 на пару, пары с BTC — от
3,1, USDT–BTC — до 100 000, USDT–SOL — до 50 000, USDT–ETH — до 100 000.
Минимумы вывода: 1 USDT, 0,0001 BTC, 0,1 GRAM.

## Как устроен расчёт

1. **Котировки.** Цены P2P — из официального P2P API Кошелька
   (`POST p2p.walletbot.me/p2p/integration-api/v1/item/online`, ключ только на
   чтение: Кошелёк → P2P Маркет → Профиль → API Keys; данные обновляются раз в
   30 секунд). Курсы внутреннего обмена — по споту Binance, Bybit добирает
   недостающее. Binance P2P опрашивается только для сравнения в `.статус` и на
   маршрут не влияет.
2. **Граф.** `fees.yaml` описывает узлы (где лежат деньги) и рёбра (операции с
   комиссиями и лимитами). Курсы привязываются к рёбрам под запрошенную сумму
   и способ оплаты.
3. **Поиск.** Поиск по лучшему первым на максимум выхода (как Дейкстра: каждая
   операция монотонна по входу — больше зашло, не меньше вышло), до 6 шагов,
   без циклов, k лучших маршрутов.
4. **Поправка.** Применяется коэффициент калибровки маршрута, в ответе —
   каждый шаг, комиссии, продавцы и на чём основана поправка.

## Запуск

```bash
make install     # .venv, зависимости, .env из шаблона
# впишите в .env WALLET_API_KEY (и данные сессии для юзербота)
make check       # ключ, живой стакан, автопроверка семантики side
make test        # тесты движка комиссий, сеть не нужна
make run         # панель на 127.0.0.1:8080
make bot         # юзербот отдельным процессом
```

`make session` превращает существующий файл `.session` Telethon в
`StringSession` без повторной авторизации.

`make check` заодно решает единственную неопределённость в документации
Кошелька: там не сказано, чью сторону описывает поле `side` в объявлении, а от
этого зависит, какую цену считать ценой покупки. Скрипт сравнивает средние
цены обеих сторон (у продавцов они обязаны быть выше) и говорит, что поставить
в `WALLET_SIDE_WHEN_BUYING`. Не запускайте панель, пока проверка не прошла:
ошибка здесь переворачивает спред.

Есть и `docker compose up -d` — панель и юзербот двумя сервисами.

### Настройки (`.env`)

| Переменная | Что это |
|---|---|
| `WALLET_API_KEY` | ключ P2P API Кошелька (только чтение) |
| `WALLET_TIER` | `basic` (обмен 0,9%) или `trader` (0,09%) |
| `WALLET_P2P_ROLE` | `taker` (0%) или `maker` (1,2–2%) |
| `WALLET_SIDE_WHEN_BUYING` | сторона объявления, у которого покупаем, — значение подскажет `make check` |
| `WALLET_MIN_EXECUTE_RATE`, `WALLET_MERCHANTS_ONLY` | фильтры контрагентов |
| `WALLET_PAYMENTS` | способы оплаты по умолчанию |
| `SAFETY_PCT` | общий запас, вычитается из итога |
| `TRACK_ROUTES` | маршруты для поминутного графика, например `USDT.WALLET>RUB.BANK:1000` |
| `HOST`, `PORT`, `PANEL_TOKEN` | адрес панели; непустой токен включает авторизацию |
| `TG_API_ID`, `TG_API_HASH`, `TG_SESSION`, `TG_ALLOWED_USERS`, `API_BASE` | юзербот |

## Юзербот

Работает на готовой сессии вашего аккаунта и ходит в API панели.

```
.к 50000 RUB.BANK USDT.WALLET   — посчитать маршрут
.узлы                           — список узлов
.статус                         — источники, точность, Wallet против Binance P2P
.факт <маршрут> <вошло> <прогноз> <получено> — записать реальную сделку
.помощь                         — справка
.raw                            — сырой текст сообщения, на которое ответили
```

Ещё он узнаёт уведомления @wallet о завершённых сделках и пишет их в лог;
автоматическая запись в калибровку намеренно выключена, пока парсер не сверен
с настоящими уведомлениями (для этого и есть `.raw`).

## Деплой на VPS

```bash
sudo deploy/install.sh     # копирует в /opt/tgrate, создаёт .venv через uv, ставит юниты systemd
make logs                  # journalctl -u tgrate-api -u tgrate-bot
```

Установщик копирует проект в `/opt/tgrate` (без `.venv`, `.git`, `data`), при
первом запуске создаёт `.env` из шаблона и останавливается, чтобы его
заполнили, затем включает `tgrate-api` и — если задан `TG_SESSION` —
`tgrate-bot`. После правок в исходниках запускайте его снова: `/opt/tgrate` —
копия, а не ссылка.

Наружу панель — только через `deploy/nginx.conf` (TLS + basic auth) и с
непустым `PANEL_TOKEN`: юзербот работает с полным доступом к аккаунту, открытая
панель этого не заслуживает.

## Структура

```
fees.yaml               граф операций и все комиссии
app/wallet.py           клиент P2P API Кошелька, тарифы, заполнение по стакану, топ продавцов
app/quotes.py           агрегатор котировок (Wallet, спот, Binance P2P), стакан на сумму
app/providers/          источники: спот (Binance + Bybit) и Binance P2P
app/graph.py            поиск маршрутов
app/models.py           применение комиссий к сумме, маршруты и шаги
app/calibration.py      поправки по реальным сделкам (SQLite)
app/history.py          срезы котировок и отслеживаемые маршруты (SQLite)
app/config.py           настройки из .env
app/main.py             API панели (FastAPI)
app/userbot.py          юзербот на Telethon
static/index.html       панель
scripts/check.py        самопроверка перед запуском
scripts/session.py      StringSession из существующей сессии
tests/                  тесты движка комиссий
deploy/                 юниты systemd, nginx, установщик
```
